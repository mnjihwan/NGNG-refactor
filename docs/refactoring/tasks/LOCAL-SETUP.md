# 통합 저장소 로컬 실행 준비

- 기준: 통합 저장소 `ab77676ae968354c47408002926119e3f3843c69`; RF-001과 별도 작업.
- 목적: 운영 클라우드 자격 증명 없이 Windows에서 각 프로젝트와 로컬 의존 서비스를 실행할 수 있는 구성을 준비한다.
- 범위: 로컬 설정·실행 문서, 로컬 S3 엔드포인트와 외부 SMS 차단, 프런트 로컬 주소, 기존 도구와 의존성 설치 및 안전한 컴파일 검증.
- 불변 조건: 운영 API와 기본 인증·인가 정책을 유지한다. 기존 운영 연결 설정을 제거하거나 운영 DB 스키마를 변경하지 않는다. 격리 로컬 DB 스키마 생성은 이후 사용자 승인을 받아 수행했으며 추가 스키마 변경은 별도 승인 대상이다. 로컬 서비스 데이터는 운영 데이터와 분리한다.
- 위험: 로컬 환경이 운영 서비스의 일관성·검색 인덱스·SMS 전달을 재현하지 않는다. 기존 테스트는 격리 전 외부 자원과 DDL에 접근할 수 있다. 개발 자격값은 개인별 ignored 설정에 보관하고, 공개 읽기 이미지 버킷은 로컬 용도로만 사용한다.
- 공유 준비: 실제 `local/backend.yml`·`local/chat.yml` 및 PC별 실행 기록은 보존하되 Git에서 제외한다. 비밀값 없는 예제와 루트 `.env.example`을 제공하고 Compose 자격값은 필수 환경변수로 전달한다. 기존 볼륨·개인 설정의 값을 덮어쓰지 않는다.
- 검증 및 남은 문제: 승인된 격리 스키마 생성과 양 서버 validate는 완료했고 `local/schema.sql`은 데이터 없는 개발용 DDL이다. Docker/WSL 복구 후 실제 서버 기동·fixture·서비스 간 연동 검증이 필요하다. [작업 기록](../REFACTORING_LOG.md)과 [로컬 개발 안내](../../LOCAL_DEVELOPMENT.md)를 참고한다.
