# RF-001 증빙 보존 범위와 검증 한계

2026-11-05 소급 정리. 이번 문서 작성에서 테스트·DB 접속·성능 측정을 실행하지 않았다. [RF-001 명세](../../tasks/RF-001.md)와 [작업 로그](../../REFACTORING_LOG.md)의 완료 판정은 테스트 컴파일 복구 및 선택 테스트 8건·독립 diff 리뷰에 한정된다.

## 남아 있는 근거와 보존 공백

- 최초 실행은 명세·[BASELINE](../../BASELINE.md)에 compileTestJava 성공, 서비스 5건·standalone MVC 3건 통과로 서술되어 있다. 최초 XML timestamp는 `2026-11-04T04:22:04`/`2026-11-04T04:22:07`로 기록됐고 XML 자체의 시간대는 명시되지 않았다. 이 최초 실행의 XML·컴파일 원시 로그는 이 증빙 경로에 별도 보존되지 않아 현재 원본과 직접 대조할 수 없다.
- [RF-002 변경 전 서비스 XML](../RF-002/before/UserServiceTest.xml)과 [컨트롤러 XML](../RF-002/before/AdminUserControllerContractTest.xml)은 RF-002 구현 전 **후일 재실행**한 8건의 원시 결과다. RF-002 증빙에는 timestamp `2026-11-04T08:04:29`/`2026-11-04T08:04:27`, 실패/오류/skip 0으로 기록돼 있다. RF-001 최초 실행 XML로 취급하지 않는다.
- [RF-002 재현 안내](../RF-002/README.md)와 `before/*.java.txt`는 그 후일 재실행 당시 테스트·운영 원본 및 환경 해시를 제공한다. 최초 RF-001 작업 트리 전체를 복원하는 자료가 아니며 당시 HEAD에 기존 미커밋 변경이 있었다.

## 한계와 추가 검증

| 추적 | 근거가 보장하는 범위 / 미실행 사유 | 후속 방법 / 재개 조건 |
|---|---|---|
| R1-증빙 | 최초 결과는 서술 기록, RF-002 XML은 별도 재실행 증거 | 당시 원본을 확보하면 출처와 식별 정보를 추가. 새 결과를 최초 결과로 소급 표기하지 않음 |
| R1-통합 | mock·standalone MVC는 DTO/Page·호출 경계만 확인. 고정 DB/외부 연동/DDL·실발송 위험 때문에 전체 test/build 미실행 | RF-016 등 격리 환경·결정적 fixture·발송 대역 확보 후 관련 묶음 실행. 실제 DB 페이지·무쓰기·동시 읽기는 RF-002 조건으로 검증 |
| R1-HTTP | 실제 보안 필터·운영 직렬화·오류 응답을 실행하지 않음. 이력 부재 NPE 관찰은 정책 승인 아님 | 안전한 HTTP 환경과 테스트 인증·정책 확인 후 역할별 상태·JSON·이력 부재·민감 필드 및 DB 상태 확인 |

최신 추적은 [BACKLOG](../../BACKLOG.md#완료-후-잔여-검증별도-후보)를 따른다. RF-003의 작은 MySQL 회귀 결과로 전체 통합·보안 검증을 충족했다고 해석하지 않는다. RF-001은 성능 작업이 아니며 측정이나 개선 주장을 포함하지 않는다. 후속 검증은 별도 범위를 정해 진행하며 자동 착수하지 않는다.
