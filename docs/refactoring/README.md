# NGNG 리팩토링 운영 지침

이 문서는 세 저장소를 함께 분석하고 작업할 때 사용하는 안내서다. 공통 규칙은 루트 [AGENTS.md](../../AGENTS.md)를 따른다. 각 저장소의 별도 지침이 있으면 해당 범위에도 적용한다. 현재 루트는 세 Git 저장소를 담은 작업 공간이므로 루트 문서는 각 저장소의 Git 이력에 자동으로 포함되지 않는다. 작업 시작 시 각 저장소의 상태와 기준 커밋을 따로 기록한다.

## 순서
1. 소스 수정 없이 세 저장소의 구조, 주요 흐름, 호출 및 연동 관계, 설정, 테스트를 분석한다. 확인한 근거와 추정을 구분하고 `ARCHITECTURE.md`에 기록한다.
2. 실행 가능한 테스트와 환경을 확인하고 `BASELINE.md`에 실행 결과와 미측정 항목을 기록한다. 기존 동작을 확인하는 테스트가 부족하면 작업별로 확보한다. 버그로 의심되는 동작은 의도된 계약으로 단정하지 않는다.
3. `BACKLOG.md`에 근거, 영향, 위험, 의존 관계, 우선순위를 기록하고 독립적으로 검증 가능한 첫 작업 하나를 선정한다. `tasks/TEMPLATE.md`를 복사해 `tasks/RF-001.md`를 작성한다. 예시 숫자나 가상의 문제를 사실로 옮기지 않는다.
4. 작업 명세의 범위와 불변 조건을 확인하고 필요한 기준선과 테스트를 확보한 뒤 최소 변경을 수행한다. 범위 확대가 필요하면 보고하고 합의한다.
5. 관련 테스트와 빌드를 실행하고 diff를 검토한다. 성능 작업이면 동일 조건으로 재측정한다. 결과와 미해결 사항을 `REFACTORING_LOG.md`에 기록한다.
6. 변경 전후를 독립적으로 검토하고 지적 사항을 해결한다. 한 작업이 끝나면 다음 작업을 자동으로 시작하지 않는다.

## 프로젝트별 확인 지점
- `NGNG-backend`: Java 17, Spring Boot 3.2.4, Gradle. API 계약, Security, JPA/트랜잭션, Redis, Elasticsearch 및 외부 연동을 변경 대상에 따라 확인한다.
- `NGNG-chat-server`: Java 17, Spring Boot 3.2.4, Gradle. WebSocket/STOMP, 메시징, 저장, 알림 및 서버 간 계약을 확인한다. 실제 연결 방식과 전달 보장은 코드와 설정으로 확인한다.
- `NGNG-frontend`: Next.js 14, React 18, TypeScript, npm. 화면 동작, API 호출, 인증 상태, 캐시 및 채팅 연동을 확인한다.
- 기능이 저장소 경계를 넘으면 호출자와 수신자, 메시지 형식 및 실패 처리를 함께 분석한다. 변경하지 않은 저장소도 영향 범위에 기록한다.

## 검증 원칙
Windows PowerShell에서 각 저장소 디렉터리로 이동한 뒤 백엔드와 채팅 서버는 `./gradlew.bat test` 또는 `./gradlew.bat build`를 사용할 수 있다. 프런트엔드는 `npm run lint`, `npm run build` 및 필요 시 `npm run cypress:open`을 검토한다. 명령은 설정에 존재한다는 뜻이며 실행 성공을 보장하지 않는다. 실제 환경, 필요한 서비스와 실행 결과를 확인한다. 의존성 설치나 외부 서비스 사용은 환경과 비용을 확인하고, 신규 의존성 추가는 승인받는다. 실행하지 못한 검증과 이유는 명시한다.

성능 비교는 대상, 기준 커밋, 데이터 규모, 동시성, 워밍업, 캐시 상태, 환경, 반복 횟수와 측정 방법을 기록한다. SQL 횟수, p50/p95, 처리량, 오류율 및 자원 사용량 중 해당 작업에 필요한 지표를 선택한다. 결과의 변동성과 부작용을 함께 평가하며 측정하지 않은 개선은 추정으로 표시한다.

## 2026-11-04 백엔드 분석 현황

이번 대상은 `NGNG-backend`다. 사용자 요청에 따라 프런트엔드와 채팅 서버는 백엔드 호출자·데이터 연동 확인에 한정해 조사했다. 애플리케이션·테스트 코드, 빌드 및 설정 파일은 변경하지 않았다.

- [ARCHITECTURE.md](ARCHITECTURE.md): 구조, 호출 관계, 데이터·캐시 경계 및 근거별 발견 사항
- [BASELINE.md](BASELINE.md): 기준 커밋, 정적 집계, 실제 컴파일 시도와 미측정 항목
- [BACKLOG.md](BACKLOG.md): 위험과 의존 관계를 구분한 독립 작업 후보
- [RF-001](tasks/RF-001.md): 첫 작업인 테스트 컴파일 복구 및 사용자 목록 계약 테스트 확보 계획
- [REFACTORING_LOG.md](REFACTORING_LOG.md): 분석 수행 범위와 남은 제약

RF-001은 테스트 컴파일 복구와 선택 테스트 8건 및 독립 리뷰를 완료했다. 전체 통합 테스트와 실제 DB·인가 검증, 서비스 성능은 확인되지 않았다. 자세한 범위와 한계는 [작업 명세](tasks/RF-001.md)와 작업 기록을 참고한다. 이후 작업은 자동으로 시작하지 않는다.
