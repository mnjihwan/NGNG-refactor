# 백엔드 리팩토링 백로그

2026-11-04. RF-001은 검증 기반 작업을 완료했으며 나머지는 분석에 따른 제안이다. 근거 F01~F09의 상세 경로·행·호출 관계는 [ARCHITECTURE.md](ARCHITECTURE.md)에 있다. 우선순위는 장애의 실측 빈도나 확정된 성능 효과를 뜻하지 않는다.

## 선정 원칙

- P0: 안전한 검증의 선행 조건, 인증·데이터 정합성 위험. 결함 재현·정책 확인을 우선한다.
- P1: 조회·캐시·실행 안정성 개선. 계약과 효과를 검증할 수 있는 작은 경계로 나눈다.
- P2: 책임·중복 정리 및 측정 후 판단할 성능 후보.
- **리팩토링**은 현재 계약을 보존한다. **결함/정책 후보**는 오류 응답·인증·잔액 규칙 등 동작 변경 가능성이 있어 순수 리팩토링과 분리한다. 승인 없이 권한·기능·스키마를 변경하지 않는다.

## 우선순위와 첫 작업의 이유

1. RF-001을 완료했다. 선택 테스트 8건은 실제 보안 필터·DB·운영 직렬화를 검증하지 않는다.
2. P0 정합성·인증 후보는 피해 가능성 때문에 우선 조사한다. 그러나 동작 변경·보안 정책 합의가 필요하므로 무조건 첫 코드 변경으로 선택하지 않는다. 기존 결함을 정상 계약으로 승인하거나 그대로 영구 보존하자는 뜻도 아니다.
3. RF-001 이후 **첫 순수 조회 개선 후보는 RF-002**다. 반복 repository 호출이 명확하고 페이지 크기·응답·최신 이력 기준을 고정해 비교할 수 있다. 실측이 없으므로 효과를 약속하지 않는다. RF-002도 자동 착수하지 않는다.
4. 캐시는 다수 쓰기 경로·다른 서버와 연결되어 더 넓은 검증이 필요하다. 일괄 추상화·DB 스키마 변경·프레임워크 업그레이드를 우선하지 않는다.

추가 보류 사항: 계좌/탈퇴 요청 ID 소유권, 가입 인증번호의 서버 검증, 신고 삭제 visible 의미, 상품 삭제 OR 조건, 제품 상세 중복 read, 업로드 중복 디코딩·워터마크 캐싱, DTO/인증 조회 중복. 각각 근거는 F03/F06~F08에 있으며 위 작업에 묶어 범위를 확장하지 않는다. 실제 동작/정책·측정 근거 확보 후 독립 명세를 만든다.
