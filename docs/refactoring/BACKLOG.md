# 백엔드 리팩토링 백로그

최신 상태(2026-11-06): 합의한 기능 중심 최소 구현·선택 검증·최종 독립 리뷰를 완료했다. 최신 기능 범위에서 수정이 필요한 결함은 발견되지 않았다. 변경 전 오프라인41건, 최종 오프라인43건(Policy28/Creation15), 격리 MySQL 기능24건 통과. 과거37건29통과/8실패는 이전 범용 내부 호출 설계의 실행 이력이며 보존한다. 임의 사전 관리 객체/active outer RR 트랜잭션은 최신 지원 범위 밖이다. 운영 배포·전체 HTTP/브라우저·성능 검증 완료를 뜻하지 않는다. [명세](tasks/RF-004.md)·[기능 증빙](evidence/RF-004/functional-implementation/README.md). 아래2026-11-05 설명과 종전 R4 표의 보류 상태는 당시 이력이며 최하단 최신 표가 우선한다.


2026-11-05 기준. RF-001은 검증 기반 작업 완료, RF-002는 최소 구현·오프라인 검증 후 전체 미완료, RF-003은 합의된 기능 검증·독립 리뷰 완료다. RF-004는 공개 Session API 재개·격리 회귀 후 서비스 경계 대안까지 검토했으나, 사용자가 추가 상세 설계·검증을 현재 결과로 보류했다. 운영 추가 구현 없이 전체 미완료·배포 부적합이다. 최신 실DB37건29통과/8실패이며 이전 보류·실패 이력은 보존한다. 나머지는 별도 제안이며 완료 작업의 한계도 아래 잔여 목록에서 추적한다. 근거 F01~F09의 상세 경로·행·호출 관계는 [ARCHITECTURE.md](ARCHITECTURE.md)에 있다. 우선순위는 장애의 실측 빈도나 확정된 성능 효과를 뜻하지 않는다.

## 선정 원칙

- P0: 안전한 검증의 선행 조건, 인증·데이터 정합성 위험. 결함 재현·정책 확인을 우선한다.
- P1: 조회·캐시·실행 안정성 개선. 계약과 효과를 검증할 수 있는 작은 경계로 나눈다.
- P2: 책임·중복 정리 및 측정 후 판단할 성능 후보.
- **리팩토링**은 현재 계약을 보존한다. **결함/정책 후보**는 오류 응답·인증·잔액 규칙 등 동작 변경 가능성이 있어 순수 리팩토링과 분리한다. 승인 없이 권한·기능·스키마를 변경하지 않는다.

## 우선순위와 첫 작업의 이유

1. RF-001을 완료했다. 선택 테스트 8건은 실제 보안 필터·DB·운영 직렬화를 검증하지 않는다.
2. 사용자는 다음 작업으로 RF-002를 지정하고 [작업 명세](tasks/RF-002.md) 확인 후 구현을 지시했다. RF-020 계좌 확인 및 RF-021 거래 소유권은 별도 P0 조사 후보로 남는다. 두 항목은 정적 의심 경로이며 실제 도달성·영향·인가 정책은 미확인이다. 수정은 재현 및 정책 확정 후 별도 범위로 정한다.
3. RF-016에서 사용자/포인트 테스트 설정·fixture 및 발송 대역을 작은 단위로 확보한다. 로컬 DB 스키마가 존재한다는 것만으로 fixture와 외부 연동의 격리가 증명되지는 않는다.
4. RF-002는 사용자 지시로 SQL 수·실행계획·지연 측정을 유예하고 최소 구현 및 오프라인 기능 검증을 수행했다. 이후 RF-003 작은 MySQL fixture에서 단건/batch 결과만 교차 확인했다. 관리자 페이지 실DB 통합·동시 읽기와 동일 조건 성능 기준선/전후 비교는 남아 전체 미완료다. [변경 전 원본·환경 해시](evidence/RF-002/README.md)를 보존했으며 성능 효과는 미측정이다.
5. 캐시는 다수 쓰기 경로·다른 서버와 연결되어 더 넓은 검증이 필요하다. 일괄 추상화·DB 스키마 변경·프레임워크 업그레이드를 우선하지 않는다.

추가 보류 사항: 탈퇴 요청 ID 소유권, 가입 인증번호의 서버 검증, 신고 삭제 visible 의미, 상품 삭제 OR 조건, 제품 상세 중복 read, 업로드 중복 디코딩·워터마크 캐싱, DTO/인증 조회 중복. 각각 근거는 F03/F06~F08에 있으며 위 작업에 묶어 범위를 확장하지 않는다. 실제 동작/정책·측정 근거 확보 후 독립 명세를 만든다.
