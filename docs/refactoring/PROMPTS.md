# 작업 요청 양식

## 최초 분석

> 루트 AGENTS.md와 docs/refactoring/README.md를 읽고 통합 저장소의 세 프로젝트를 분석해 줘. 소스 코드는 수정하지 말고 구조, 호출·연동 관계, 주요 기능, 의존성, 기존 테스트 및 검증 환경을 조사해 줘. 설계, 예외 처리, 데이터 접근, 캐시와 성능 후보를 실제 근거와 추정으로 구분해 줘. ARCHITECTURE.md, BASELINE.md, BACKLOG.md를 갱신하고 검증 가능한 첫 작업 한 건을 선정해 tasks/RF-001.md에 범위, 위험, 테스트와 완료 조건을 작성해 줘. 측정하지 않은 값은 미측정으로 기록하고 분석 후 멈춰 줘.

## 개별 작업

> AGENTS.md와 docs/refactoring/README.md, tasks/RF-NNN.md를 읽고 지정된 한 작업만 수행해 줘. 호출 관계와 불변 조건을 확인하고 필요한 기존 동작 테스트와 기준선을 확보한 뒤 명세 범위 내에서 변경해 줘. 관련 검증과 diff 확인 후 결과, 미실행 이유 및 남은 위험을 REFACTORING_LOG.md에 기록해 줘. 명세 밖의 변경이 필요하면 이유를 보고하고, 다음 작업은 자동으로 시작하지 마.

## 독립 리뷰

> RF-NNN 명세와 변경 전후 diff, 관련 호출자 및 검증 결과를 독립적으로 검토해 줘. 외부 계약, 인증·인가, 데이터 정합성, 트랜잭션, 동시성, 실패 처리와 성능 근거를 확인해 줘. 발견 사항은 심각도, 위치, 재현 조건과 영향 순으로 보고하고, 실행하지 못한 검증과 남은 위험을 명시해 줘. 근거 없는 성능 개선 주장은 구분해 줘.
